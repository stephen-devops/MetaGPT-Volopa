## Shared Knowledge

The project uses existing Volopa platform infrastructure including OAuth2 authentication middleware, FX conversion services, file storage, and multi-tenant client scoping. All database tables follow platform conventions with either flag-based soft delete (deleted + delete_time) or Laravel SoftDeletes (deleted_at). Currency validation uses existing platform master data. User roles (Primary Admin, Admin, Business User, Card User) are platform-wide. The system implements three core domains: User Permission Management (granting OOP feature access), Single Expense CRUD with FX conversion, and CSV Batch Upload with async processing. All API responses use Laravel API Resources for consistent formatting and security. Queue-based processing prevents API blocking for file uploads. The pocket_expense table supersedes the older oop_expenses design and should be used for all implementations.

## Anything UNCLEAR

All core requirements are clearly defined. Minor clarifications needed: 1) Notification channel for batch upload completion (email vs in-app) - this doesn't block development as the trigger point is specified, 2) Exact table naming convention (singular vs plural) for existing platform tables like 'user'/'users' and 'client'/'clients' - this can be resolved by checking the actual database schema during implementation, 3) FX service integration specifics for commission calculation, but the interface contract is well-defined, 4) Audit logging mechanism choice, but the requirement is clear that permission grants/revokes need auditing.
