## Shared Knowledge

The system uses Volopa's existing OAuth2 middleware for authentication and client scoping. All services share the FXConversionService for currency calculations with client-specific commission rates. The PocketExpenseCSVValidator preloads reference data (currencies, countries, categories) to optimize batch validation. Database connections use utf8mb4 encoding with proper foreign key constraints. Soft delete patterns vary: Laravel SoftDeletes trait for file uploads, flag-based (deleted + delete_time) for expense tables. All API responses use Resource classes to hide internal fields and provide consistent formatting. Queue jobs process uploads in 100-record batches for performance. The user permission system supports delegation where admins can grant management rights to other users regardless of role hierarchy.

## Anything UNCLEAR

Three areas need clarification: (1) The specific notification mechanism for batch upload completion - should we implement in-app notifications, email notifications, or both? The specs reference notification but don't specify the channel. (2) The FX conversion integration pattern - while we know there's an existing /wallet-ccy-value endpoint and FX infrastructure, the exact API contract for retrieving historical FX rates with client-specific commissions needs to be defined. (3) The audit logging implementation - should we use Laravel's built-in activity log package, implement a custom audit table, or use an event sourcing pattern for tracking permission grants/revokes and expense modifications? These decisions will impact the final implementation approach but don't block the core system architecture.
