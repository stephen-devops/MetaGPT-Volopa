## Full API spec

openapi: 3.0.0
info:
  title: OOP Expense Management API
  version: 1.0.0
paths:
  /api/expenses:
    get:
      summary: List user expenses
      responses:
        200:
          description: Paginated expense list
    post:
      summary: Create new expense
      requestBody:
        content:
          application/json:
            schema:
              type: object
              properties:
                amount: { type: number }
                currency: { type: string }
                description: { type: string }
      responses:
        201:
          description: Expense created
  /api/expenses/{id}:
    get:
      summary: Get expense details
    put:
      summary: Update expense
    delete:
      summary: Delete expense
  /api/expenses/{id}/approve:
    patch:
      summary: Approve expense
  /api/expenses/{id}/reject:
    patch:
      summary: Reject expense
  /api/uploads/pocket-expense/csv:
    post:
      summary: Upload CSV file
      requestBody:
        content:
          multipart/form-data:
            schema:
              type: object
              properties:
                file: { type: string, format: binary }
                expense_user_id: { type: integer }
                client_id: { type: integer }
  /api/uploads/{id}/status:
    get:
      summary: Get upload status
  /api/permissions:
    get:
      summary: List user permissions
    post:
      summary: Grant permission
  /api/permissions/{id}:
    delete:
      summary: Revoke permission
  /api/fx/convert:
    post:
      summary: Convert currency amounts
  /api/fx/rates:
    get:
      summary: Get exchange rates

## Shared Knowledge

Follow Laravel conventions: migrations use timestamps, models use Eloquent relationships, services handle business logic with database transactions, controllers stay thin with dependency injection, policies authorize actions, FormRequests validate and authorize, API Resources transform responses. Use Redis for caching FX rates and reference data. Queue jobs process in batches of 100 records. All monetary amounts use decimal precision. Status enums: pending, approved, rejected for expenses; uploading, validating, completed, failed for uploads.
