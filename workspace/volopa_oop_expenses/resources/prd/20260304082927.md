## Original Requirements

Build the Volopa OOP (Out-of-Pocket) Expenses API System using Laravel 10+ with PHP 8.2+. Three modules: 1. User Management & Permissions — RBAC via user_feature_permission with delegation hierarchy 2. Pocket Expense CSV Batch Upload — synchronous validation, async background sync 3. Single Expense Data Capturing — CRUD with FX conversion and flexible metadata

## Product Goals

- Enable comprehensive out-of-pocket expense tracking for Volopa clients
- Provide flexible role-based permission system with delegation capabilities
- Support both single entry and bulk CSV upload workflows
- Automate FX conversion for multi-currency expense management
- Ensure secure API-first architecture with proper validation
- Maintain data integrity through atomic operations and proper error handling
- Integrate seamlessly with existing Volopa platform infrastructure
- Deliver scalable expense metadata capture for flexible business requirements

## User Stories

- As a Primary Administrator, I want full access to all users' expenses so I can manage the entire client organization
- As an Administrator, I want to manage expenses for delegated users so I can support my team efficiently
- As a Business User, I want to create and manage my own expenses so I can track my out-of-pocket spending
- As a Card User, I want to record personal expenses incurred for business so they can be reimbursed
- As an Admin, I want to delegate expense management rights to other users so I can distribute workload
- As a user with management rights, I want to create expenses on behalf of managed users so I can assist with data entry
- As an Admin, I want to upload CSV files with multiple expenses so I can efficiently process bulk historical data
- As a user, I want automatic FX conversion when entering foreign currency expenses so I don't need manual calculations
- As a user, I want to override FX conversion rates when I have more accurate information
- As a user, I want to attach metadata like categories and tracking codes so expenses are properly classified
- As a user, I want to configure custom expense sources so I can track different payment methods
- As an Admin, I want detailed validation errors for failed CSV uploads so I can correct data issues
- As a Primary Admin, I want to revoke management rights when delegation is no longer needed
- As a user, I want to receive notifications when batch uploads complete so I know the status
- As an API consumer, I want consistent error response formats so I can handle failures properly

## Requirement Analysis

The Volopa OOP Expenses system requires a sophisticated multi-module architecture addressing three distinct domains: user permission management with delegation hierarchy, bulk CSV processing with atomic validation, and single expense CRUD with real-time FX conversion. The system must integrate with existing Volopa infrastructure (OAuth2, FX services, notification system) while maintaining strict data validation and security. Key technical challenges include: (1) Complex RBAC with dynamic delegation that doesn't follow traditional role hierarchies, (2) Synchronous CSV validation for up to 200 rows with detailed error reporting, (3) Real-time FX conversion with 30-day lookback and commission calculation, (4) Flexible metadata system supporting various expense classification schemes, and (5) Multi-tenancy with client-scoped data isolation. The API-first design must support both web and mobile consumers with consistent error handling and response formatting.

## UI Design draft

API-first system with RESTful endpoints under /api/v1 namespace. Core endpoints: (1) Permission management: GET/POST /user-feature-permissions for delegation, (2) Expense CRUD: GET/POST/PUT/DELETE /pocket-expenses with nested metadata, (3) Batch upload: POST /pocket-expenses/upload-csv with multipart file handling, (4) Source config: GET/POST/PUT/DELETE /expense-sources for client customization. All responses follow consistent JSON structure with data/errors/meta sections. Request validation uses Laravel Form Requests with detailed field-level error messages. Authentication via OAuth2 middleware on all routes. File uploads stored in Laravel storage with background job processing. FX conversion triggered via dedicated /fx-convert endpoint with debounced frontend calls. Error responses include HTTP status codes (400/401/403/404/422) with structured error objects containing field, message, and code properties.
