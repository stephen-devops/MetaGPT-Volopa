## Implementation approach

We will implement a Laravel 10+ API system with three core modules: User Management (role-based permissions with delegation), CSV Batch Upload (synchronous validation with background processing), and Single Expense Data Capturing (flexible metadata with FX conversion). The architecture follows the Controller-Service-Model pattern with thin controllers delegating to service classes containing business logic. We'll use FormRequest classes for validation, Policies for authorization, API Resources for consistent JSON responses, and Queue Jobs for async processing. Database design uses proper foreign key constraints, indexes for performance, and separate tables for each module to avoid conflicts. OAuth2 middleware protects all endpoints with client data isolation. The system implements DB transactions for multi-write operations, eager loading to prevent N+1 queries, and comprehensive caching for reference data.

sequenceDiagram
    participant C as Client

    Note over C,AR: Permission Grant Flow
    C->>AC: POST /api/permissions/grant
    AC->>FR: GrantUserFeaturePermissionRequest
    FR->>P: UserFeaturePermissionPolicy.create()
    P-->>FR: authorized
    FR-->>AC: validated data
    AC->>S: UserPermissionService.grantPermission()
    S->>M: DB::transaction begin
    S->>M: UserFeaturePermission.create()
    M-->>S: permission model
    S->>M: DB::transaction commit
    S-->>AC: permission
    AC->>AR: UserFeaturePermissionResource
    AR-->>AC: formatted response
    AC-->>C: 201 Created JSON
    
    Note over C,AR: CSV Upload Flow
    C->>AC: POST /api/uploads/pocket-expense/csv
    AC->>FR: PocketExpenseCSVUploadRequest
    FR->>P: PocketExpensePolicy.create()
    P-->>FR: authorized
    FR-->>AC: validated file
    AC->>S: PocketExpenseCSVValidator.validateCsv()
    S->>S: loadReferenceData() [cached]
    S->>S: validateRow() for each row
    alt validation fails
        S-->>AC: validation errors array
        AC->>M: PocketExpenseFileUpload.update(status=failed)
        AC-->>C: 422 Validation Error JSON
    else validation passes
        S->>M: DB::transaction begin
        S->>M: PocketExpenseFileUpload.create()
        S->>M: bulk insert to pocket_expense_uploads_data
        S->>M: DB::transaction commit
        S->>J: dispatch ProcessPocketExpenseUpload
        S-->>AC: success result
        AC-->>C: 200 Success JSON
        J->>S: PocketExpenseService.createExpense() [background]
        S->>M: PocketExpense.create() [batch of 100]
        S->>M: PocketExpenseMetadata.create() [batch]
    end
    
    Note over C,AR: Single Expense Creation Flow
    C->>AC: POST /api/pocket-expenses
    AC->>FR: StorePocketExpenseRequest
    FR->>P: PocketExpensePolicy.create()
    P-->>FR: authorized
    FR-->>AC: validated data
    AC->>S: PocketExpenseService.createExpenseWithMetadata()
    S->>S: FXConversionService.getFXRate()
    S->>M: DB::transaction begin
    S->>M: PocketExpense.create()
    M-->>S: expense model
    S->>M: PocketExpenseMetadata.create() [multiple]
    S->>M: DB::transaction commit
    S-->>AC: expense with metadata
    AC->>AR: PocketExpenseResource
    AR-->>AC: formatted response
    AC-->>C: 201 Created JSON
    
    Note over C,AR: Expense List with Permissions
    C->>AC: GET /api/pocket-expenses

    S-->>AC: expenses collection
    AC->>AR: PocketExpenseResource.collection()
    AR-->>AC: formatted response
    AC-->>C: 200 OK JSON
