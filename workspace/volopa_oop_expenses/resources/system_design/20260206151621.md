## Implementation approach

We will implement a Laravel API system following the controller-service separation pattern with comprehensive role-based access control. The architecture uses thin controllers delegating to service layer for business logic, FormRequests for validation, Policies for authorization, and API Resources for consistent JSON responses. CSV upload processing uses synchronous all-or-nothing validation with background queue jobs for large operations. Real-time FX conversion integrates with external API services with 30-day rate caching. Permission management implements hierarchical delegation through user_feature_permission table. Database design includes proper indexes, foreign key constraints, and transaction boundaries. The system uses Redis for caching reference data and Laravel queues for async processing.

sequenceDiagram
    participant C as Client
    participant EC as ExpenseController
    participant CER as CreateExpenseRequest
    participant EP as ExpensePolicy
    participant ES as ExpenseService
    participant FXS as FxConversionService
    participant OE as OopExpense
    participant ER as ExpenseResource
    participant PUC as PocketExpenseUploadController

    participant PUS as PocketExpenseUploadService
    participant CSV as PocketExpenseCSVValidator
    participant PFU as PocketExpenseFileUpload
    participant Job as ProcessPocketExpenseUploadJob
    
    Note over C,ER: Single Expense Creation Flow
    C->>EC: POST /api/expenses
    EC->>CER: validate request data
    CER->>EP: authorize user can create
    EP-->>CER: return authorization result
    CER-->>EC: return validated data
    EC->>ES: createExpense(data, user)
    ES->>FXS: convertAmount(amount, from, to, date)
    FXS-->>ES: return converted amount
    ES->>OE: create expense record
    OE-->>ES: return expense model
    ES-->>EC: return created expense
    EC->>ER: transform expense to resource
    ER-->>EC: return formatted response
    EC-->>C: return 201 with expense data
    
    Note over C,Job: CSV Upload Flow
    C->>PUC: POST /api/uploads/pocket-expense/csv
    PUC->>UPR: validate upload request
    UPR-->>PUC: return validated data
    PUC->>PUS: processUpload(file, user, expense_user_id, client_id)
    PUS->>PUS: validateCsvStructure(file_path)
    PUS->>CSV: validateCsv(file_path)
    CSV->>CSV: validateRow for each row
    CSV->>CSV: validateDataTypes(row_data)
    CSV->>CSV: validateCrossFields(row_data)
    CSV-->>PUS: return validation results
    alt validation failed
        PUS->>PFU: create upload record with errors
        PFU-->>PUS: return upload record
        PUS-->>PUC: return validation errors
        PUC-->>C: return 422 with errors
    else validation passed
        PUS->>PFU: create upload record as validated
        PFU-->>PUS: return upload record
        PUS->>Job: dispatch background processing
        Job->>ES: createExpense for each row
        ES->>OE: create expense records
        PUS-->>PUC: return success response
        PUC-->>C: return 200 with upload status
    end
